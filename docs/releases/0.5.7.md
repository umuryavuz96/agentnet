# agentnet 0.5.7

Setup of an existing workspace no longer leaves you stuck, and a new agent no longer dies at Claude Code's first-run questions.

**Setup scan**

- The read-only scan session has its own name, "setup-scan" (shown as "Setup scan"). It no longer registers or shows as the director ("root"). The real director can always join after it.
- Say "go", "yes", "apply" or "finalize" in the scan session's chat and it applies the setup itself. It uses the same path as the Apply button, with the same backups and Rollback. If you made a plan in the panel, that plan is used. Without one, the default picks are used. It asks you first if files outside the workspace (~/.claude) change.
- Line edits are checked again when you apply. If the text moved in the file, it is found again by its content. If the text is gone, that one edit is skipped and listed in the result. You never have to check line numbers.
- The scan session can send a new report while you are still deciding. The newer report replaces the old one and the plan is reset. No cancel or rescan is needed.
- Leftovers of the old agmsg setup (its tool server, hooks and lines in CLAUDE.md files) are selected by default in the plan. Other lines in the same finding stay off.

**Spawning agents**

- A new agent in a folder Claude Code has not seen before no longer dies at the "trust this folder" and ".mcp.json servers" questions. Before it starts, the spawner trusts the folder and enables only the servers the agent needs (playwright by default, `--mcp a,b` to change it). All other servers found are disabled. Answers already given are kept. `agentnet trust <dir>` does the same by hand.
- If a session still ends before it joins, the spawn output now shows the last lines of its screen, so the reason is never silent.
